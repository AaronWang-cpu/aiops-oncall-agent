# 设计：收敛工作区并重做诊断页

## Context

诊断后端在 P4 之后已经产出三类前端尚未使用的事实：`diagnosis.tool_evidence`（证据元数据，`data` 为空）、`diagnosis.query_records`（每次查询的问题、工具、参数、状态与失败原因）、`diagnosis.budget`（用量与阶段截止时间）。工具的真实返回只落在证据表里，经 `/aiops/diagnostics/{id}/evidence-chain` 一次性回载。前端旧实现把执行链、工具审计、假设与结论堆在同一栏，并用工具审计里的 `resultSummary`（只含 `evidenceIds`）充当工具输出，导致“看不到证据”。

同时，工作区提供与告警处理无关的对话与知识库两个板块，默认落地页还是对话。

## Goals

- 工作区只围绕告警处理：选择告警或输入问题 → 发起诊断 → 观看过程 → 读结论、证据、账本与报告。
- 让持久化证据成为一等公民：可浏览、可打开、可核对，截断范围显式说明。
- 让额度与查询明细可见，使“假设驱动 + 预算约束”在界面上可解释。
- 窄屏不隐藏任何信息列。

## Non-Goals

- 不改后端、合同与数据库；不改诊断算法、预算默认值。
- 不为对话与知识库保留隐藏入口。
- 不引入图表库或新的 UI 依赖。

## Decisions

1. **检查器用分页而非堆叠**：结论与假设、现场证据、调查账本三视图共用一个可滚动检查器，默认展示结论。原因是三块内容都属于“当前任务的判读材料”，同屏堆叠会让页面重新变得臃肿；分页让每屏只承担一件事。
2. **证据抽屉优先于常驻列表**：列表只给 kind、来源、摘要与时间，点击后抽屉展示结构化内容（指标点表格、日志/变更记录字段、其它形状的键值列表），并在末尾保留默认折叠的原始返回内容。这样既保证信息密度，也保证可核对性。
3. **截断显式化**：抽屉最多渲染 10 行/条，并明确写出“共 N 点/条，此处显示前 10，其余未显示”，不静默丢弃。
4. **旧数据降级可读**：旧引擎写入的证据 `summary` 可能是 JSON 字符串。前端检测到 `{`/`[` 开头时改用“来源 + 结构化返回”标签，正文交由抽屉渲染，避免把 JSON 当标题。
5. **进度只认后端**：任务卡进度取 `task.status.progress`，没有该字段时显示等待态而不是 50/65 之类的估算值。
6. **证据引用即入口**：假设依据中的证据 ID、执行链里工具调用写入的证据，都是打开抽屉的按钮，保证“从结论回到事实”只有一次点击。

## Risks

- 删除对话与知识库前端会让 RAG 与文档管理在界面层不可演示：已与用户确认，属于本次取舍。
- 旧任务证据形状与新任务不同：以契约字段为准渲染，未知形状降级为键值列表并保留原始内容。
- 检查器分页可能被误认为信息缺失：分页标签固定显示三个视图名称，未选中视图不会消失。

## Migration Plan

1. 删除对话与知识库模块、路由、导航与相关测试，默认落地页改诊断。
2. 重排诊断工作区并新增证据/账本视图与抽屉，同步更新布局与组件测试。
3. 同步 OpenSpec 规格与文档站点，归档本次变更。

## Verification

- `npm run frontend:typecheck`、`npm run frontend:test`、`npm run frontend:build`。
- 真实浏览器三档宽度检查：无横向溢出、无控制台错误、三个检查器视图可切换。
- 选择存在持久化证据的历史任务，确认证据列表、抽屉与账本渲染真实内容。
- `openspec validate --all`、`npm run docs:build`。
